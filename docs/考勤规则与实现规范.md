# 考勤规则与实现规范

最后更新：2026-08-12

## 1. 文档目的

本文档是福拉特考勤统计应用的业务规则入口，供业务人员核对，也供 AI 和开发人员实现、评审及测试时使用。它同时描述：

- 已确认的业务口径；
- 程序当前已经实现的行为；
- 原始制度中存在、但程序尚未实现的规则；
- 仍需业务确认、禁止自行推断的事项；
- 输入输出契约和实现约束。

原始资料位于 `docs/references/`，未决事项的详细讨论位于 `docs/待确认事项.md`。
应用内展示内容来自 `docs/当前考勤规则.md`。凡是会改变用户可见计算结果的规则变更，必须同时更新该文件。

## 2. 规则状态与优先级

### 2.1 状态定义

| 状态 | 含义 | 开发要求 |
| --- | --- | --- |
| 已实现 | 业务口径明确且代码已实现 | 修改时必须补充或更新测试 |
| 已确认待实现 | 业务口径明确，但代码尚未实现 | 可按本文档实现 |
| 待确认 | 来源之间冲突，或缺少数据来源/边界定义 | 不得猜测，不得静默实现 |
| 制度参考 | 原始制度有描述，但不属于当前输出范围 | 未经确认不得扩展需求 |

### 2.2 信息优先级

发生冲突时按以下顺序处理：

1. 本文档中的“已确认”结论；
2. `docs/待确认事项.md` 中后续记录的业务结论；
3. 自动化测试所表达的既有行为；
4. 当前代码行为；
5. 原始规则 Excel 和补充 DOCX。

如果高优先级内容仍无法消除冲突，应新增待确认编号，而不是选择一个看似合理的口径。

## 3. 输入契约

### 3.1 输入文件

输入必须是钉钉导出的完整 `.xlsx` 考勤报表，并包含以下工作表：

| 工作表 | 当前用途 | 必需字段 |
| --- | --- | --- |
| `打卡时间` | 完整性校验 | 姓名、工号、UserId、打卡时间 |
| `原始记录` | 统计“不在可打卡时间范围”的记录 | 姓名、工号、考勤日期、打卡时间、打卡结果 |
| `月度汇总` | 员工主清单、加班及各类请假汇总 | 姓名、工号、工作日加班、休息日加班、节假日加班、加班总时长 |
| `每日统计` | 日期、班次、每日打卡、缺卡、旷工及每日加班 | 姓名、工号、日期、班次、上班1打卡时间、下班1打卡时间、加班总时长 |

缺少工作表或必需字段时必须终止生成并给出明确错误，不允许输出部分结果。

工作簿可另外包含 `年假明细` Sheet，用于计算年假剩余小时，必需字段为工号、姓名、公司、截止当前月剩余（小时）。缺少该 Sheet 时其他考勤数据仍可生成，但年假剩余小时留空并输出警告。

### 3.2 考勤月份

- 状态：已实现。
- 从 `每日统计` 的日期列自动读取年份和月份。
- 日期为空时终止；出现多个年月时终止。
- UI 不提供手工月份参数。

### 3.3 员工标识

- 内部关联优先使用工号；工号为空时使用钉钉 UserId。
- 配置匹配优先使用工号；配置项没有工号时才按姓名匹配。
- 输出必须包含工号。
- 不得仅按姓名合并两个具有不同工号的员工。

## 4. 配置规则

### 4.1 不参与考勤人员

- 状态：已实现。
- 命中配置后，在计算开始前完全过滤。
- 不得出现在 `考勤明细`、`考勤汇总表` 或 `异常打卡明细`。

### 4.2 特殊人员

特殊人员由应用设置维护，不应在 Rust 计算逻辑中硬编码姓名。

| 分组 | 加班时长 | 餐补目标口径 | 当前状态 |
| --- | ---: | --- | --- |
| 按打卡计算餐补 | 强制为 0 | 仅按实际打卡计算，不看加班流程 | 已实现 |
| 工作日/周末无加班（法定节假日正常） | 工作日、周末强制为 0；法定节假日正常计算 | 全日期仅按实际打卡计算出勤及加班餐补，不看加班流程 | 已实现 |
| 不打卡但有餐补 | 强制为 0 | 在职区间内每个法定工作日记 1 次，不依赖打卡或每日排班；不计算加班餐补 | 已实现 |
| 无餐补、无加班 | 强制为 0 | 固定为 0 | 已实现 |
| 六天制（每日 8 小时、无餐补） | 全部强制为 0 | 固定为 0 | 已实现 |
| 六天制（每日 4 小时、无餐补） | 全部强制为 0 | 固定为 0 | 已实现 |

另有“弹性到岗（8:30 分界）”特殊人员分组。该分组只调整迟到、早退的时间基准，不强制清零加班，也不改变其适用的餐补规则。外置示例名单包含张一成（工号 26333），人员匹配仍优先使用工号。

同一人员允许同时加入“弹性到岗（8:30 分界）”和“按打卡计算餐补”，两项规则叠加执行。除此之外，特殊人员分组之间仍互斥；“不参与考勤人员”也不能同时出现在任何特殊人员分组中。

六天制按周一至周六计算正常工作日，法定节假日不计应出勤；所有日期均不统计加班，平时、周末、法定加班和每日加班全部强制为 0。外置示例名单包含廖传兰（每日 8 小时）和廖传霞（每日 4 小时）；两人在当前样例中没有工号，暂按姓名匹配。

应用不内置特殊人员名单，首次运行使用空配置。原默认名单保存在 [`examples/settings/考勤设置默认名单.json`](../examples/settings/考勤设置默认名单.json)，由用户按需导入；设置页面支持导入和导出 JSON，不提供恢复预置功能。

特殊人员配置不设置生效日期：保存后立即生效，删除后立即失效。重新生成历史月份时也使用当前保存的名单，不维护生效月份、失效月份或历史版本。

## 5. 考勤明细规则

### 5.1 行列结构

- 每名员工占两行：`出勤` 行和 `加班` 行。
- 每日出勤状态写入出勤行；每日加班小时写入加班行。
- 月末汇总列位于每日列之后。
- 非工作日使用灰色底纹。已内置年份按年度节假日 JSON 修正法定放假日和调休工作日，未内置年份回退为公历周六、周日并给出警告。
- 年度数据来自 `NateScarlet/holiday-cn`，构建时校验国务院公告来源和结构后编译进应用；生成考勤表时不访问网络。
- 设置可维护 `statutoryHolidayDates` 三倍工资日清单。某年存在清单日期时，该年以清单区分法定加班和周末加班；该年没有配置时继续将年度 JSON 中所有 `isOffDay=true` 的节假日日期视为法定加班日。此覆盖不改变工作日、调休和餐补计算。

### 5.2 符号

| 含义 | 符号 | 示例 |
| --- | --- | --- |
| 正常出勤 | `√` | `√` |
| 休息或未排班 | `☆` | `☆` |
| 迟到 | `D` + 分钟 | `√D8` |
| 早退 | `Z` + 分钟 | `√Z15` |
| 病假 | `△` + 小时 | `△8` |
| 事假 | `O` + 小时 | `O4` |
| 旷工 | `X` + 小时 | `X8` |
| 年休假 | `N` + 小时 | `N8` |
| 婚假 | `H` + 小时 | `H8` |
| 产假/陪产假 | `M` + 小时 | `M8` |
| 丧假 | `S` + 小时 | `S8` |
| 出差 | `C` | `C` |
| 育儿假 | `Y` + 小时 | `Y8` |
| 哺乳假 | `B` + 小时 | `B1` |
| 产检假 | `P` + 小时 | `P4` |
| 调休 | `T` + 小时 | `T8` |

### 5.3 跨日请假

- 状态：已实现。
- 钉钉可能在请假涉及的每一天重复显示同一流程总时长。
- 程序先按完整流程文本去重，再把总小时数从流程覆盖的最后一天向前分配，每天最多 8 小时。
- 以“天”为单位的流程，每个出现日期按 8 小时处理。
- 同日既有出差又有请假时，保留 `C` 前缀，例如 `CO4`。

### 5.4 迟到、早退与缺卡标记

- 状态：已实现。一般人员仅按钉钉最终标记处理；弹性到岗人员按下述专用规则处理。
- 一般人员只有打卡结果明确为“迟到”或“早退”时才计算分钟数。
- 分钟数由班次起止时间与实际打卡时间之差计算；次日打卡加 24 小时处理。
- 上班或下班缺卡时，在当日出勤标记后追加 `缺卡`。
- “弹性到岗（8:30 分界）”人员：
  - 08:30（含）之前到岗，不记迟到，正常下班时间为 17:30；
  - 08:30 之后到岗，也不记迟到，正常下班时间为 18:00；
  - 早退分钟数按当天对应的正常下班时间和最后一次下班打卡计算；
  - 无法取得上班打卡时，不推测当天应为 17:30 还是 18:00，仍按缺卡处理。
- 原始制度中的哺乳假、公差、半天请假、南京支援滁州弹性班次等豁免尚未自动识别。新员工入职日期已通过“入职名单”识别。

## 6. 汇总规则

### 6.1 本应出勤小时

- 状态：已实现。
- `本应出勤小时 = 有有效班次且班次不为“休息”的日期数 × 8`。
- 当前按排班数据计算，不使用月度汇总中的“出勤天数”。
- 有入离职信息时，只统计入职日（含）至离职日（含）的有效班次；区间外日期不计应出勤、旷工或异常。
- “不打卡但有餐补”人员不依赖每日排班记录，按在职区间内的法定工作日数乘以 8 小时计算。
- 六天制人员不直接采用钉钉的排班天数，按在职区间内的周一至周六重新确定应出勤日。每日 8 小时组按天数乘 8，每日 4 小时组按天数乘 4；按天统计的旷工和假期也使用对应每日小时数。

### 6.2 实际出勤小时

- 状态：已实现。
- 公式：

```text
正常出勤小时 = max(本应出勤小时 - 全部请假小时 - 旷工小时, 0)
实际出勤小时 = 正常出勤小时 + 平时加班 + 周末加班 + 法定加班
```

- 请假小时包括：事假、调休、病假、年假、哺乳假、婚假、产假/陪产假、丧假、例假、育儿假和产检假。
- 婚假、产假/陪产假、丧假、例假由天数乘以每日应出勤小时数转为小时；普通人员和六天制 8 小时人员按 8 小时、六天制 4 小时人员按 4 小时换算。
- 育儿假和产检假按去重后的流程时长计算。
- 全部不计算加班的特殊人员三类加班均为 0，因此实际出勤不包含加班；“工作日/周末无加班（法定节假日正常）”人员仅保留法定加班并计入实际出勤。
- “不打卡但有餐补”人员以法定工作日每天 8 小时为基数，仍按上述统一公式扣除请假和旷工，不因缺少打卡或每日排班记录而将出勤基数记为 0。

### 6.3 加班

- 状态：已实现。
- 平时、周末、法定加班读取钉钉月度汇总的最终核定小时数，再应用统一的加班计费梯度。
- 配置三倍工资日的年份优先使用每日加班时长重新划分周末和法定加班；缺少每日加班数据的人员无法重分，保留钉钉月度分类并输出警告。
- 每日加班读取 `每日统计` 的加班总时长；如缺少每日行，则从月度每日结果中的“加班 N 小时”补充。
- 当每日核定加班大于 0、加班申请开始时间不晚于 17:30，且最后下班卡达到 19:30（含）时，先扣除 17:30-18:00 的 0.5 小时晚餐时间。19:30 前下班或加班申请从 17:30 后开始时不扣除；跨日下班同样视为达到 19:30。申请开始时间从月度汇总的每日“加班 MM-DD HH:MM 到……”流程文本读取，不使用当天首张上班卡代替。
- 加班计费梯度为：不满 1 小时计 0；达到 1 小时后，每完成 0.5 小时增加 0.5 小时，未满下一个半小时的尾数向下舍去。边界示例：`0.99 → 0`、`1.0 → 1.0`、`1.49 → 1.0`、`1.5 → 1.5`、`1.99 → 1.5`、`2.0 → 2.0`。
- 晚餐时间扣除发生在半小时梯度折算之前；两项规则同时应用于每日加班、月度平时/周末/法定加班及实际出勤中的加班时长。餐补计算仍使用钉钉原始审批时长与实际打卡时长，不使用扣除或折算后的计费时长。
- 程序不自行扣除 12:00-13:00 等休息时间，默认钉钉已完成审批和有效时长核定。
- 六天制人员没有加班口径：每日加班以及平时、周末、法定加班汇总全部写 0，实际出勤不增加加班小时。
- “工作日/周末无加班（法定节假日正常）”人员的工作日、周末每日加班和汇总均写 0；法定节假日每日加班、法定加班汇总及实际出勤继续使用统一的扣除与计费梯度规则。

### 6.4 出差

- 状态：已实现。
- 出差天数按月度每日结果中包含“出差”的日期数统计。

### 6.5 请假与旷工

- 年假从月度每日考勤结果中的年假流程读取，与每日 `N` 标记使用同一数据来源。病假、事假、调休和哺乳假优先读取钉钉月度汇总小时数；对应汇总单元格为空时，从逐日审批流程回退统计。
- 婚假、产假/陪产假、丧假和例假优先按钉钉月度汇总天数乘以每日应出勤小时数；汇总单元格为空时，从逐日审批流程回退统计。普通人员和六天制 8 小时人员按 8 小时、六天制 4 小时人员按 4 小时换算。
- 逐日流程回退时，同一流程先去重，跨月流程只保留本月有效工作日和起止时间对应的小时；同一天多笔同类请假合并累计，避免明细互相覆盖。
- 育儿假和产检假按去重后的流程时长统计。
- 旷工小时为每日旷工天数之和乘以每日应出勤小时数；普通人员和六天制 8 小时人员按 8 小时、六天制 4 小时人员按 4 小时换算。
- 年假剩余小时读取 `年假明细` Sheet 的“截止当前月剩余（小时）”。该字段是不含报表当月的期初余额，输出余额为该值减去同源汇总的本月年假小时数。
- 年假明细优先按工号匹配；工号为空时按姓名匹配，并兼容月度汇总姓名末尾的“（离职）”。未匹配或同名且无法唯一识别时保持空白并输出警告，不猜测人员对应关系。

### 6.6 所属公司

- 入职/离职名单命中时，优先使用名单中的“所属公司”。
- 其他人员从当前模板的历史 `考勤明细` 按姓名沿用所属公司。
- 未匹配时按考勤组回退：包含“滁州”记为 `滁州`，包含“昆山”记为 `KSFAE`，其他记为 `JSFAE`。
- 未被名单和历史表匹配时，才按考勤组回退判断。

## 7. 异常打卡与绩效分数

### 7.1 分类

| 分类 | 统计方式 |
| --- | --- |
| 未签到 | 没有上班卡，按次数统计；整天无打卡也记 1 次 |
| 未签退 | 没有下班卡，按次数统计；整天无打卡也记 1 次 |
| 迟到/早退 10 分钟以内 | 人事行政部每次均统计；其他部门每人每月前 2 次豁免，只统计超出部分 |
| 迟到/早退 11-30 分钟 | 每次记 1 次；为避免与下一档重叠，程序按 11-29 分钟计算 |
| 迟到/早退 30-120 分钟 | 累加分钟数，恰好 30 分钟归入本档 |
| 不在范围内打卡 | `原始记录` 中结果包含“当前不在可打卡的时间范围” |

`异常打卡明细` 不输出“未打卡（次）”列。备注只写入已被上述字段计数的异常；非人事行政部被豁免的前 2 次 10 分钟内异常不写入备注。超过 120 分钟的迟到/早退当前不进入分档；无法从班次和打卡时间计算分钟数的记录会产生警告。

### 7.2 绩效扣分公式

```text
绩效扣分 = 未签到次数
         + 未签退次数
         + 10 分钟以内超出豁免后的次数
         + 不在范围内打卡次数
         + 11-30 分钟次数 × 2
         + ceil(30-120 分钟累计分钟数 / 30)
```

只有存在实际计数异常的员工才进入异常表。

## 8. 餐补规则

### 8.1 输出列定义

- 状态：已实现。
- `考勤明细` 中第一列“餐补”按行区分：出勤行写工作日出勤餐补，加班行写加班餐补。
- “餐补次数”写两类餐补合计。
- 当前程序写入已计算的出勤餐补、加班餐补及两者合计；明确无餐补时写数值 0。

### 8.2 出勤餐补

原始规则：

- 工作日上午 10:00（含）前完成上班打卡，记 1 次；
- 有出差流程的当天不享受餐补；
- 居家办公不享受餐补；
- 新员工入职当天即使打卡异常也应记餐补。

工作簿中的“入职名单”提供入职日期。普通人员入职当天为工作日时，即使打卡缺失或异常也记 1 次出勤餐补；出差、居家办公不适用该例外。特殊餐补人员仍优先遵循其分组口径。

### 8.3 工作日加班餐补

原始 Excel 写明：

| 条件 | 餐补次数 |
| --- | ---: |
| 加班至 19:00 | 0 |
| 加班至 19:30 | 1 |
| 加班至 24:00 | 2（含 19:30 阶段的 1 次，另加 24:00 阶段的 1 次） |

口径已确认：补充 DOCX 中“至 19:30 记 1 次；至 24:00 记 1 次”的第二个“1 次”是新增一次。因此工作日加班至 24:00 当天合计 2 次，不覆盖 19:30 阶段的餐补。

### 8.4 周末和法定节假日加班餐补

上午、下午、夜间分别判断，每段内的有效在岗时间分别达到 2 小时才记 1 次，全天加班分段后汇总：

| 分段 | 原始条件 |
| --- | --- |
| 上午 | 加班至 12:00，在岗且该段不少于 2 小时 |
| 下午 | 加班至 19:30，在岗且该段不少于 2 小时 |
| 夜间 | 加班至 24:00，在岗且该段不少于 2 小时 |

周末和法定节假日分为上午至 12:00、13:00-19:30、19:30-24:00 三个有效段，12:00-13:00 午休不计。每段分别达到 2 小时记 1 次。无加班审批不计算加班餐补；有审批时，审批时长与实际打卡形成的加班时长取较短值。跨过 24:00 的加班和餐补归属加班开始日。

### 8.5 特殊人员餐补

- “按打卡计算餐补”：出勤餐补和加班餐补均忽略审批，仅按实际打卡判断。工作日沿用 10:00、19:30 和 24:00 阈值；周末/节假日按第一张上班卡至最后一张下班卡分段，每段实际在岗达到 2 小时记 1 次。该类人员的加班小时仍强制为 0。
- “工作日/周末无加班（法定节假日正常）”：餐补口径与“按打卡计算餐补”相同，全部日期都忽略审批并仅按实际打卡判断；工作日和周末仅清零加班时长，不清零正常出勤餐补或加班餐补，法定节假日同时保留加班时长和餐补。
- “不打卡但有餐补”：按在职区间内的法定工作日每天记 1 次出勤餐补，不依赖打卡或每日排班记录，不计算加班餐补。
- “无餐补、无加班”：餐补固定为 0。
- 两类六天制人员：出勤餐补和加班餐补均固定为 0，同时不统计任何加班。

## 9. 制度参考但当前未实现

以下规则存在于原始 Excel，但当前输出和程序未实现：

- 每月最多两次补卡机会；
- 事假、病假最小单位 0.5 小时；
- 调休结余转加班费及春节调休负值；
- 年假资格、折算、额外 6 天和跨年限制；
- 婚假、产假、陪产假、流产假、哺乳假、丧假、育儿假的资格审核；
- 夜班补贴 30 元/天；
- 销售人员特殊加班费规则；
- 补卡、病假材料、夜班邮件等审批材料校验。

这些内容不得因为“制度里有”就直接加入当前计算范围。

## 10. 输出契约

输出工作簿固定包含：

1. `考勤明细`：每人两行、逐日状态和逐日加班、月度汇总；
2. `考勤汇总表`：每人一行的工号、姓名及汇总字段；
3. `异常打卡明细`：仅包含有异常的员工及扣分明细。

年假余额已接入 `年假明细` Sheet；匹配成功时输出计算值（包括 `0` 和负数），未匹配或匹配不唯一时留空并使用浅黄色标识。餐补属于已计算字段，明确无餐补时写数值 `0`。

## 11. AI 开发约束

AI 或开发人员修改考勤逻辑时必须遵守：

1. 先定位本规则中的状态和待确认编号，再修改代码。
2. 不得把 UI 文案、历史输出值或单个员工结果当成通用规则。
3. 不得按姓名硬编码特殊人员；使用设置配置并优先按工号匹配。
4. 不得在数据缺失时默认为 0；未知值使用空白/`None` 并给出警告。
5. 不得自行推导节假日；必须有明确年度日历数据源。
6. 解析逻辑、计算逻辑、输出格式应分层，避免在写 Excel 时重复计算。
7. 每项规则修改至少增加一个正常用例和一个边界/异常用例。
8. 涉及真实样例的测试只能校验必要结果，错误日志不得批量输出员工明细。
9. 规则变更后同步更新本文档和 `docs/待确认事项.md`。
